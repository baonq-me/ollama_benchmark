# Ollama Benchmark Results JSON Format Specification

## Overview

This document describes the JSON schema for benchmark results generated by the Ollama Benchmark CLI tool. The format is designed to be consumed by both the benchmark engine (for writing results) and the React dashboard (for visualization).

## File Structure

The results file (`results.json`) is a single JSON object with the following top-level structure:

```json
{
  "metadata": { ... },
  "results": [ ... ]
}
```

## Schema Definition

### Root Object

| Field | Type | Description |
|-------|------|-------------|
| `metadata` | `object` | Configuration and environment information for the benchmark run |
| `results` | `array` | Array of benchmark results, one entry per prompt size tested |

### Metadata Object

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `model` | `string` | Yes | The Ollama model name used for benchmarking (e.g., "llama3.2") |
| `endpoint` | `string` | Yes | The Ollama API endpoint URL (e.g., "http://127.0.0.1:11434") |
| `gen_tokens` | `integer` | Yes | Number of tokens to generate in each request |
| `iterations` | `integer` | Yes | Number of iterations per prompt size |
| `concurrent` | `integer` | Yes | Number of concurrent requests (1 = sequential) |
| `retries` | `integer` | Yes | Maximum retry attempts per request |
| `retry_delay` | `float` | Yes | Initial delay in seconds between retries |
| `timestamp` | `string` | Yes | ISO 8601 formatted timestamp when benchmark started |

### Results Array

Each element in the `results` array represents benchmark data for a specific prompt size.

#### Result Entry Object

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `prompt_size` | `integer` | Yes | Target input prompt size in tokens |
| `runs` | `array` | Yes | Array of individual benchmark run results |
| `stats` | `object` | Yes | Aggregated statistics across all runs |

### Runs Array

Each element represents a single benchmark execution.

#### Run Object

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `ttft_ms` | `float` | Yes | Time to First Token in milliseconds |
| `input_tps` | `float` | Yes | Input throughput (tokens processed per second) |
| `output_tps` | `float` | Yes | Output throughput (tokens generated per second) |
| `total_latency_ms` | `float` | Yes | Total request latency in milliseconds |
| `prompt_tokens` | `integer` | Yes | Actual number of input tokens used |
| `output_tokens` | `integer` | Yes | Actual number of output tokens generated |
| `retries_used` | `integer` | Yes | Number of retry attempts made (typically 0) |

### Stats Object

Contains statistical aggregations for each metric across all runs.

#### Stats Structure

| Metric | Fields | Description |
|--------|--------|-------------|
| `ttft_ms` | `median`, `p95`, `p99`, `min`, `max` | Time to First Token statistics |
| `input_tps` | `median`, `p95`, `p99`, `min`, `max` | Input throughput statistics |
| `output_tps` | `median`, `p95`, `p99`, `min`, `max` | Output throughput statistics |
| `total_latency_ms` | `median`, `p95`, `p99`, `min`, `max` | Total latency statistics |

Each statistic field is a float representing the computed value in the appropriate unit (milliseconds for latency, tokens/second for throughput).

## Complete Example

```json
{
  "metadata": {
    "model": "llama3.2",

    "gen_tokens": 512,
    "iterations": 5,
    "concurrent": 1,
    "retries": 3,
    "retry_delay": 2.0,
    "timestamp": "2026-05-15T01:30:00.000000"
  },
  "results": [
    {
      "prompt_size": 256,
      "runs": [
        {
          "ttft_ms": 45.23,
          "input_tps": 125.5,
          "output_tps": 85.3,
          "total_latency_ms": 6234.56,
          "prompt_tokens": 260,
          "output_tokens": 512,

        },

      "stats": {

          "median": 44.56,
          "p95": 45.23,
          "p99": 45.23,

        "input_tps": {
          "median": 126.85,

        "output_tps": {

      }

  ]

```

## Validation Rules

- All metric values must be non-negative numbers
- `prompt_size` values should be sorted ascending in the results array
- `runs` array length must equal `metadata.iterations`
- All required fields in `stats` must be present for each result entry
